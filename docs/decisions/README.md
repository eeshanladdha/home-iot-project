# Architecture Decision Records

Use an ADR when a decision materially affects architecture, cost, security, maintainability or future phases.

## Template
### ADR-NNN: Title
**Status:** Proposed / Accepted / Superseded

**Context**
What problem are we solving?

**Options considered**
1. Option A
2. Option B
3. Option C

**Decision**
What was selected?

**Rationale**
Why?

**Evidence**
Link experiment/test results.

**Consequences**
What changes or trade-offs follow?

**Review trigger**
What evidence would cause us to revisit the decision?

## Expected topics
- Raspberry Pi OS
- Local-first architecture
- Docker vs native services
- Event transport
- Database/storage
- Camera processing location
- AI provider
- Local vs cloud LLM
- Network segmentation
- Backup/recovery
